Critical: live default admin credentials work.
I confirmed POST /api/auth/login with admin / admin123 returns an admin session on production. The seed code hardcodes this credential in auth.ts.
Fix now: change/delete that admin account, invalidate sessions, audit recent activity, and remove or hard-gate the default seed path.

High: credentialed CORS is open to arbitrary origins.
app.ts uses cors({ origin: true, credentials: true }). A live request with Origin: https://evil.example returned Access-Control-Allow-Origin: https://evil.example and Access-Control-Allow-Credentials: true, including for an authenticated /api/auth/me request.
Fix: allowlist only your real frontend origins, add CSRF protection for cookie-auth writes, and set auth/API responses to Cache-Control: no-store.

High: non-admin staff roles can mutate sensitive workforce data.
requireAuth only checks for any staff session, not admin access, in workforce.ts. Write endpoints like creating workers, editing workers, and verifying certifications use requireAuth instead of requireAdmin: see lines 313, 456, and 857.
Fix: make mutating endpoints admin-only or add explicit permission checks per role.

Medium/high: arbitrary certification files can be uploaded and served inline.
Workforce cert upload uses multer with size limits only, no MIME allowlist, in workforce.ts. It stores client-provided req.file.mimetype and later serves it back inline; legacy http file URLs redirect. This can become stored XSS or phishing if HTML/SVG is uploaded and viewed by staff.
Fix: allowlist PDF/JPEG/PNG/WebP, validate file magic bytes, add X-Content-Type-Options: nosniff, prefer Content-Disposition: attachment, and stop redirecting arbitrary http URLs.

Medium: deployment controls are weak.
The GitHub repo is public, main is unprotected, and the production commit is unsigned/verified false. The branch API reports "protected": false.
Fix: enable branch protection, require PR review/status checks, require signed commits if practical, and restrict production auto-deploys.

Medium: no login throttling found.
Auth routes directly compare bcrypt hashes with no rate limiter on admin or worker login paths. Combined with the live default admin credential, this is especially exposed.
Fix: add IP/account rate limits, lockout/backoff, and MFA for admin users.
